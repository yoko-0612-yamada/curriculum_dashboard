# dashboard 回帰テスト

本体を変更せず、現在の `dashboard.py` の処理を検証します。本番CSVは使用せず、全書込み先を `TemporaryDirectory` に限定します。通常終了・テスト失敗時とも一時データを削除します（プロセス強制終了時は保証外）。

## 実行

`Git_Clone_カリキュラム` ディレクトリで:

```sh
.venv/bin/python -B -m unittest discover -s curriculum_dashboard/tests -t curriculum_dashboard -v
```

アプリと同じ環境（pandas、numpy、Streamlit）が必要です。今回の環境にはpytestがないため標準unittestで実行しています。pytestが導入済みの場合も収集できる構成です:

```sh
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest -p no:cacheprovider curriculum_dashboard/tests
```

`-O` は使用しないでください。一部のデータ処理テストでは通常のassertを使用しています。UIテストは作業ディレクトリとStreamlitの実行状態を使うため、同一プロセス内で並列実行しないでください。

## 構成・自動確認の範囲

| ファイル | 対象 |
|---|---|
| support.py | 本体のトップレベル関数をAST抽出。起動処理・デコレータは実行せず、CSV/JSONパスを一時領域へ変更 |
| test_csv_and_seats.py | 検定結果の未作成・正常空・読込失敗時の非上書き、slot正規化、note保存、座席移動の対象範囲・使用予定、構文 |
| test_schedule.py | 17取込シナリオ×固定/月予定、キャンセル・再追加のBot/人数、取消表示用行の維持、隔週5週、月予定優先・確定空 |
| test_progress.py | course_id、名称変更、別コース/生徒、曖昧/不一致の旧履歴の警告、課題所属変更、有効課題条件 |
| test_progress_ui.py | 一時コピーのAppTest。通常/検定の空CSVから初回保存→再読込→更新、未作成/不正時の非保存、OFF履歴保持→ON復帰 |
| fixtures/csv_headers.json | 合成データ作成用のCSVヘッダーのみ。実データの行は含まない |

座席人数は現行CSV仕様の `base_count - absence_count` を確認します。キャンセル後再追加は、実際の取込検証・反映関数が生成する例外行を用います。

固定予定保存の共通関数使用はASTによる構造チェックも含みます。意図的に保存経路を変更した際はテストも見直してください。関数抽出テストは画面の接続・キャッシュ・全起動順序を保証しません。進捗の少数の保存テストだけ、合成データ上で本体のUI処理を実行します。

## 手動確認（必ず本番と分離したコピーで）

- 座席画面: 基本席から他席へ生徒を選択し、元席が空席になること。保存・再表示後も新席だけに残り、別日・別コマ・他生徒・複数の「使用予定」が維持されること。自動テストはコールバック単位であり、選択UIへの接続と保存後再表示は手動。
- iPad実機/PC: 全コマを縦スクロールして席1〜5のヘッダー固定、色、列位置、選択UIを確認。
- 月カレンダー: キャンセルの取消線・グレー表示を確認。自動テストは表示用行の保持まで。
- システム設定: 数値slotの追加・更新・削除、週次画面から再表示。自動テストは正規化と保存データ処理を確認し、フォーム操作は手動。
- 固定予定: システム設定のnoteを週次画面で別予定/週指定/種別を編集して保存しても保持すること。自動テストは共通保存処理と全保存経路の呼出し構造まで。
- コース管理: 旧履歴がある状態で名称を変更・保存・再起動して完了状態を確認。自動テストは履歴対応付けとID判定まで。すでに名称が失われた旧履歴は推測せず警告するのが仕様。

課題の所属コースを変更しても、既存進捗のcourse_idは移動されません。変更先コースの完了へ自動流用されないことをテストしています。履歴移行を行う仕様は追加していません。

## 運用

修正前後に同じコマンドを実行し、失敗した期待値を安易に書き換えず、本体の仕様変更か退行かを判断してください。これは列挙した重要仕様の回帰検出であり、アプリ全機能の保証ではありません。

## 退会予定・第1段階の追加テスト

`test_student_enrollment.py` は開始日/終了日の境界、旧データ、日付不正、
0人と取得失敗の区別、月予定の0人、基本席の非破壊フィルタと明示的な更新・削除を確認します。
基本席操作・月予定生成・読込停止は、該当する本体ASTブロックを一時データで実行します。
画面全体の操作ではありません。コード構造を変えた場合は抽出箇所のテストも見直してください。

日付関数は生徒専用で、現行の業務画面には未接続です。
開始・終了日は両端を含み、片側空欄はその側の制限なし、両方空欄のみ従来のis_active判定です。
日付が明示されている場合は期間を正とし、現在のis_activeで過去在籍を打ち消しません。
不正日付・逆転期間はValueErrorで通知し、0人と混同しません。
既存画面には終了日がまだ適用されないこともテストしています。

次段階では、`ensure_students_optional_cols` がjoin_dateを `errors="coerce"` で変換する前の
元データを検証してください。変換後のNaTだけから、元の不正文字列と空欄を復元することはできません。
共通日付関数は元データを検証するためのものです。
今回変更した在籍0人の経路以外は、既存のis_active判定を一括置換していません。
生徒管理で確認して行う退会時の基本席解除は維持し、起動時フィルタだけの削除を廃止しています。

## 退会予定・第2段階

`test_schedule_enrollment.py` は日次予定専用入口

出席・座席・Bot・今日の表示・カレンダーの既存呼出し元は変更していません。
